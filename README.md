# Анализ A/B-эксперимента AI-рекомендаций

Код анализирует 11 CSV из School of Analytics Hackathon 2026. Основная метрика —
GMV на пользователя; решение также учитывает записанную маржу, возвраты и поддержку.
Исходные CSV не изменяются. Коммиты и отправка в Git не выполняются кодом.

## С чего начать

1. Открой `analysis.ipynb`: краткий итоговый анализ, ключевые результаты, три графика и рекомендация.
   Подробная предыдущая версия сохранена в `analysis_full.ipynb`.
2. Прочитай `src/config.py`: там даты, допущения, число повторений и бизнес-пороги.
3. Посмотри `src/preprocessing.py`: он определяет аудиторию и собирает пользовательскую витрину.
4. Прочитай `src/statistics.py`: формулы критериев и доверительных интервалов.
5. Сопоставь выводы с `reports/analysis_report.md` и исходными таблицами.

## Установка и запуск

Из корня проекта, Python 3.10 или новее:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run_analysis.py
```

В текущей среде зависимости уже установлены в `.venv`. Для повторения проверенных
версий используй `reports/requirements-tested.txt`; это список основных пакетов,
а не полный lock-файл всех транзитивных зависимостей.

В VS Code выбери интерпретатор `.venv/bin/python` для ноутбука. Для исполнения
без интерфейса:

```bash
.venv/bin/python scripts/execute_notebook.py
```

Итоговый ноутбук читает готовые таблицы из `reports/tables/`. Если изменились исходные
данные или настройки, сначала обнови расчёты через `run_analysis.py`. Числовые выводы
и графики обновляются при исполнении ноутбука; авторские пояснения нужно пересмотреть.

`scripts/create_notebook.py` создаёт шаблон краткого ноутбука и заменяет его текущие
ячейки/выводы. Обычно запускать его повторно не требуется.

Настройки меняются в `src/config.py`. Пример переопределения параметров без правки:

```bash
.venv/bin/python run_analysis.py --bootstrap-repeats 3000 --permutation-repeats 2999
```

Параметр `--observation-end YYYY-MM-DD` задавай только при подтверждённой полноте
выгрузки к этой дате. Последняя дата события не подтверждает полноту наблюдения.
После этого добавляется оценка возвратов за фиксированный срок среди созревших заказов.

## Как читать результаты

- `reports/tables/metrics.csv`: эффекты test − control, интервалы, p-value и поправки.
- `reports/tables/user_metrics.csv`: витрина, одна строка на пользователя.
- `reports/tables/quality_checks.csv`: ошибки связей останавливают расчёт; предупреждения требуют интерпретации.
- `reports/tables/cleaning_log.csv`: сколько пользователей и событий затронули исключения.
- `reports/tables/bootstrap.csv`: дополнительная проверка интервалов на уровне пользователей.
- `reports/tables/interactions.csv`: различия эффектов между исходными сегментами.
- `reports/tables/sensitivity.csv`: результат с ботами, по первичному назначению и с отсечкой хвоста.
- `reports/tables/break_even_costs.csv`: предельная дополнительная цена AI-показа при разной цене обращения.
- `reports/figures/`: графики; `reports/analysis_report.md`: объяснение каждого.
- `reports/run_metadata.json`: настройки, версии и SHA-256 исходных CSV.

Доли в CSV — от 0 до 1. Эффект `0.01` равен **1 процентному пункту**, а
`relative_effect_pct` — относительное изменение в процентах. Например, рост
CTR с 0.08 до 0.09 означает +1 п.п. и +12.5% относительно control.
Интервалы индивидуальные, до поправки. Holm применяется к четырём подтверждающим
метрикам: GMV/user, маржа/user, доля пользователей с возвратом и с обращением в
эксперименте. Вторичные, распределительные и сегментные проверки имеют отдельные
FDR-семейства. Определения сохранены в `metric_definitions.csv`.

## Принятые решения по данным

- Основная выборка исключает конфликтующие назначения и `is_bot_candidate=1`.
  Это не полный ITT; исключения могут влиять на причинную интерпретацию.
- Первичное назначение определяется по единственной группе в самую раннюю дату.
  Его применение к конфликтующим пользователям — чувствительность; внутридневной
  порядок назначения неизвестен и требует подтверждения до причинного вывода.
- Пользователи без активности остаются с нулями. Это предполагает полный журнал событий.
- Помеченные показы имеют уникальные ID и связанные клики/заказы; восстановимого
  оригинала по естественному ключу нет. Они сохраняются, а CTR без них проверяется
  отдельно. Связанные реальные покупки автоматически не удаляются.
- Заказы ограничены 01–30 июля 2026. Возвраты и обращения внутри эксперимента
  отделены от записанных последующих событий. Без даты полной выгрузки последние
  не считаются завершённым наблюдением после каждого заказа.
- `gross_margin_rub` уже учитывает записанные возвраты. Они повторно не вычитаются.
  Историческую маржу на 30 июля из итогового поля восстановить нельзя.
- Доставка не заполняется для основной метрики и не объявляется расходом.
  Отдельная таблица сравнивает суммы платежей при нулевом и медианном заполнении.
- Возвращённый GMV — стоимость заказов, не доказанная сумма возмещения.
  Условный net GMV включается только через `assume_full_refund=True`.
- Экономические сценарии используют дополнительные расходы поддержки и AI сверх
  записанной маржи. Это не чистая прибыль. Значения сетки — сценарии, не согласованные бюджеты.
- Категории — исходы на всей аудитории. Не применяется сегментация по купленному
  товару как по признаку, существовавшему до воздействия.

Для отношений сумм (CTR, средний чек, возвраты/заказы) дисперсия рассчитывается
по пользователям, с ковариацией числителя и знаменателя. Bootstrap также пересэмплирует
пользователей. Для KS с множеством нулей используется перестановочная калибровка.
Отсутствие значимости не доказывает отсутствие вреда; пороги ухудшения пока не заданы.
Асимптотический тест взаимодействия для редких сегментных событий пропускается.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты сравнивают Welch с SciPy, проверяют кластерную дисперсию, неопределённые
знаменатели, нулевые события, воспроизводимость bootstrap и KS с совпадениями.
Также проверяются неактивные пользователи, конфликты, боты, сохранение покупок
помеченных показов и поздние возвраты без повторного вычитания маржи.

Методология: [SRM](https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/),
[Welch](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ttest_ind.html),
[Манна–Уитни](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.mannwhitneyu.html),
[KS](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ks_2samp.html).
